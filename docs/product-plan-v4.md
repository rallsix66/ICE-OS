# ICE v4 产品方案

> 2026-10-13 · 方案验证版。用户已授权设计文档与独立 Demo；真实数据接入、权限迁移、数据库改造和生产发布均未授权执行。
> 现状依据：[current-analysis.md](current-analysis.md)。本方案不是已上线能力清单。

## 定位与目标

以商品身份为核心、库存为基础、货物流转为主线的经营管理系统。经营者要看资源在哪里、哪些市场积压、哪些商品长期不动；运营要看缺货、运输、映射和同步异常。它不是财务账、完整 WMS、采购结算或自动调拨系统。

第一阶段成功标准：同一商品能从公司货号和69编码找到各来源 SKU；同一票货能同时看到飞书业务状态、API轨迹和独立库存快照；到货不会伪造 BigSeller 增量；六个核心视图可以交互评审，完整设计可在仓库追溯。

## 商品身份

- 保留 Product 的 UUID 技术主键和 ProductVariant 层。页面、搜索、导入和人工匹配优先公司货号，禁止生成替代业务货号。
- Product 包含公司货号、标准名称、外贸中英文名称、规格、单位、图片引用和分类。69编码作为字符串标识保存，保留前导零；可能一品多包装码，不能擅自当作单一全局主键。
- `product_identifier` 管理69编码及明确类型的其他标识；`product_mapping` 管理来源系统/账号/仓库/国家 SKU 到 Variant 的关系。商品不是所有同名 SKU 的自动集合。
- 生命周期：未匹配 → 待确认 → 已确认；来源漂移进入重新核对；不再使用进入停用。未匹配/待确认/重核/停用不进入“已确认商品库存”自动归集，原始数量保留在异常区域。
- 每次确认、重核、换绑和停用生成新版本和操作日志；历史快照保留当时映射，不随当前换绑被改写。
- 当前归集须同时检查最新映射仍已确认、与快照记录的映射版本一致；转重核/停用后立即从当前商品合计排除，原始量转入异常区。重绑后等待新有效快照或明确审批的版本化重新解释，不将旧历史偷偷归给新商品。

## 四个数据来源

BigSeller 决定海外数量，聚水潭决定国内数量，飞书物流表决定货票商品/数量/人工业务状态，喜运达 API 只增强物流轨迹。各源都保留原始标识、采集/业务时间和批次，不相互冒充权威。

库存快照记录实物数量和可售数量，二者不能混用；BigSeller 来源在途字段仅是来源观测值，不再加到飞书在途。未知、缺失、失败和零库存必须分别表达。同步失败显示旧快照及陈旧时间，不清零，不生成“最新成功”时间。

喜运达绑定按物流商 + 来源账号 + 运单号精确候选匹配，再验证市场/仓库范围。缺账号、同号多候选、市场冲突均进入待绑定；不能按运单号模糊命中就覆盖绑定。外部轨迹中的签收不等于飞书“已到货上架”。

## 流转与数量规则

1. 发货的国内减少由聚水潭下一快照体现；DIS 展示发货事件和在途，不能额外扣库存。
2. 飞书运输中/清关中/派送保留未到货数量；部分到货逐明细扣除已经确认的到货量。
3. 飞书“已到货上架”结束对应在途，不增加海外库存；等待 BigSeller 快照。
4. 新完整、有效 BigSeller 批次改变海外库存。不能用“前后库存差刚好等于发货量”证明某票已被吸收，期间可能同时有销售/调整/退货。
5. 若库存先更新而飞书未到货，使用明确收货证据关联/人工对账；证据不足时分开展示，不给可加总的去重总量/总货值。到货但未同步亦标“待快照确认”。
6. 不在同一个可加总数字里叠加飞书在途、BigSeller来源在途和已吸收库存。可核对数、未确认数、陈旧数分开。

## 货值口径（待业务确认，不是财务结算）

Demo 采用虚构的人民币标准单位成本，按实物数量估值，明确“估算货值”。正式成本来源、含税/运费口径、估值日和币种策略待确认。

- 国内货值 = 已确认映射且有有效成本的国内实物数量 × 对应版本单位成本。
- 海外货值同理，按库存所在市场分组；在途货值按目的市场分组。
- 可售量独立展示，不充当实物货值数量；当前生产 `inventory.quantity` 不能直接复用为该估值分母。
- 缺成本、缺映射、异币未换算不记成0；展示已估值小计、覆盖率和缺口数量。跨币先有明确汇率/日期/版本，不静默相加。
- 库存与货票不同步时，不制造“总资产恒定”的漂亮数字。阶段数可显示，整体合计若存在无法去重项则标待核对。
- 无出入库/销售流水时，“长期无流动”只能是快照长期未变线索，不能当作滞销已证实；正式周转判断还需销售/调整来源。

## 六个核心视图

### 经营总览

展示国内、在途、海外估算货值与成本缺口；泰国/菲律宾/马来西亚/越南/印尼市场分布；商品、可售、缺货风险和在途指标；近期流转以及映射、同步、待绑定、缺成本、快照陈旧异常。指标必须可追溯到列表/来源，不在首页陈列用户授权范围。

### 商品库存

公司货号、69编码、名称、国内/五市场库存、在途和估值。支持货号/条码/外部SKU搜索、市场过滤、空结果恢复。点击商品进入同页详情，看到身份、全部来源映射、库存来源、历史批次、关联货票和操作日志。

### ICE 商品库

展示人工维护商品资料、规格/单位/中英文名称、图片和分类；缺图显示明确占位，不编造真实商品照片。展示五种映射状态；Demo 确认/重核仅改变本地会话并追加演示日志，重置恢复，不调用数据库。

### 物流详情

货票号、目的市场、运单绑定信息、商品明细、飞书状态与备注、API时间线并列。三个观察阶段可切换：运输 → 飞书到货但库存未变 → 新快照体现变化；额外解释逆序证据缺口，不让API推进业务状态。

### 库存快照

来源、仓库、SKU、映射货号、实物/锁定/可售、来源在途、采集时间、批次、完整性/新鲜度。历史快照不可编辑，失败批次不发布。详情显示原始口径和映射版本；筛选无需真实抓取。

### 操作日志

谁、何时、对象、动作、来源、市场、货号、69编码、货票和关联批次；可按时间/人员/市场/业务标识查找。商品、映射、状态、同步、快照发布、权限修改均纳入设计。Demo 种子日志及会话内模拟变化明确分辨，不声称防篡改审计已实现。

## 权限目标

三个业务角色，不建复杂企业组织树：管理员维护商品、映射、用户和配置；负责人读取所辖市场经营信息；运营维护所辖市场日常业务和备注、提交映射候选，不能确认商品身份或改系统授权。

权限拆成角色动作 + 市场/仓库范围 + 金额权限。默认最小权限：负责人按授予的市场读取金额，运营默认不看金额；最终配置规则需要正式安全验收。管理员也必须启用且有有效会话。

金额限制必须在服务端 DTO、受限表/RPC、导出、日志和错误信息中执行，不能仅CSS隐藏。Demo 角色切换只是虚构数据视角演示，不是真实安全控制；真实三角色未上线。

## 第一阶段边界与后续门

### 本轮产品反馈：Demo交互补齐（2026-10-13）

用户在首版六视图后要求补齐同步/权限设置、首页库存展示、商品资料用途和市场物流集中查看。本轮在同一mock模块增加两个设置入口，不执行真实接入：

- 首页提供国内实物、海外实物、海外可售、飞书剩余在途数量，以及可追到商品详情的完整商品库存概览；不增加跨阶段简单合计，不照搬参考HTML的最近操作区。
- ICE商品库改为“商品资料表 / 来源映射复核”两个分区，取代仅作为详情入口的大摘要卡片。
- 物流主界面变为市场 + 状态 + 搜索的货票表，列出商品/数量、飞书状态/备注、最新API节点、预计到仓和缺成本；点开单票详情并保留筛选。时序教学收起。补充同市场多票/部分到货/已完成虚构样本。
- 数据同步提供四源说明、有效仓批次、模拟启停/读取频率/成功失败检查。不收集凭据，检查成功也不改变库存或成功采集时间。
- 权限设置模拟Admin/Manager/Operator市场、金额和映射操作配置。非管理员不能保存配置，负责人/运营不能获得映射确认权；管理员可关闭自身映射操作但保留权限配置入口。空市场不给全量，切换视角后投影所有演示记录；不把权限范围放到首页。
- 参考文件只读分析，不复制其中脚本、用户或商品数据。参考版“负责人可确认映射”等权限不自动移植，保持本项目既定边界。现有操作日志UI保留，不按参考版重做。
