## 1. 范围与决定

V5 的选择性吸收以 [产品方案](product-plan-v4.md) 为准：补充经营视角和可追溯解释，不替换本架构、不新增九套服务。本期估值排除运费及费用分摊；复杂分析和智能化仍不在实施范围。

- 脱离的是 Supabase 平台依赖，包括托管数据库地址、Auth、PostgREST/RPC 传输、SDK 和 service-role 后台接口；不是把整套 Supabase 搬到自己的服务器。
- 采用标准 PostgreSQL 作为业务和历史存储；保留 Product → ProductVariant → Inventory、业务 UUID、ICE 人工货号及四个来源的权威边界。
- 推荐复用 Next.js/TypeScript 模块化单体：页面、Server Actions/HTTP 入口、领域服务、Repository 不推倒重写。独立后端是自主运行的服务端能力，不要求立刻另建 NestJS/Go 服务。
- 推荐同仓独立 worker 进程承接同步、日统计、重放与补数，避免长任务依赖页面请求存活；现有 Python 抓取器可继续采集，但写入必须走新的受控发布边界。
- 当前只预留并定义历史数据合同与查询接口；不做 BI 页面、预测、复杂钻取、通用事件总线、微服务或第二套数仓。
- 上述后端部署形态是建议实现；具体认证库、PostgreSQL 主版本、服务器、备份存储、域名与预算在实施任务中确认，不视为已部署或已采购。

### P0-02 后续方案（2026-10-15 用户确认，本轮不实施）

- 不迁移旧 Supabase 业务数据，不沿用旧 SKU/商品映射；正式账号与权限在启用阶段重建。
- 真实来源接入后由用户重新确认匹配；部署与生产接入按后续阶段安排。
- 删除旧 Supabase 环境的前置条件：P0-02 独立审查通过，且现役入口/同步不再依赖旧 Supabase（用户已授权满足条件后删除，不长期保留）。

## 2. 推荐运行结构

```text
浏览器（现有 ICE 页面；不持有数据库凭据）
  → Next.js 服务端入口（独立会话 + 启用检查 + 授权 + Zod）
  → 领域服务 / Repository
  → PostgreSQL（普通业务角色 + 最小 GRANT + 原生 RLS）

四源 → source adapter → 暂存/校验 → 发布事务 → 历史事实 + 当前投影 + 操作日志
                                         ↓
                         worker 重算日统计 → 授权历史查询/未来分析页面
```

单数据库优先，建议逻辑区分业务、认证、金额和后台任务的访问权限，而不是提前拆成多数据库。`pg` 已作为开发依赖存在，但尚无生产 PostgreSQL 适配器；是否提升运行依赖在实现任务中验证，不据此声称已完成替换。

## 3. 模块所有权

| 模块 | 拥有的数据与职责 | 不可承担的职责 |
|---|---|---|
| 身份与授权 | 独立用户/会话、启用状态、角色、市场/仓库、金额能力 | 不信任客户端传入的用户、角色或 scope |
| 商品身份 | 商品资料版本、辅助编码、Variant、来源映射版本 | 不按同名/SKU 自动合并商品 |
| 来源接入 | 账号范围、同步运行、校验、幂等、失败证据 | 不把缺失/失败转成零或发布不完整批次 |
| 库存 | 不可变快照、当前指针、可售兼容投影 | 不接受物流到货加库存或二次扣国内库存 |
| 货票/物流 | 飞书明细状态与修订、收货证据、独立 API 轨迹 | API 不替飞书改状态；不凭库存差判断收货 |
| 历史统计 | 选点规则、日历、依赖水位、版本化日统计及重算 | 不成为库存写入者，不篡改原始事实 |
| 成本/估值 | 版本成本、汇率、估值口径、覆盖率 | 缺成本不是零，不泄露金额给无权限用户 |
| 审计 | 成功事务同写日志、失败另留证据 | 不以日志替代业务历史、不得记录密钥 |

## 5. 独立认证与数据库权限

- 选择维护中的可自部署认证组件，不自行设计密码学或会话协议。具体组件尚待小范围验证；它必须支持服务端可撤销会话、停用用户、会话失效、重置密码和安全 cookie。
- 自有业务用户保留原 UUID；若认证组件使用自己的 ID，建立唯一身份映射，不重写商品/日志/授权的用户外键。密码哈希兼容性不能假定；不兼容时走受控重设密码和重新登录，不迁移旧会话 token。
- 登录限流、CSRF/来源校验、HttpOnly/Secure/SameSite、退出撤销、权限撤销时效及管理员恢复流程是替换验收内容。会话/用户敏感表不开放给普通业务查询。
- 应用授权检查角色动作 + 当前获准市场/仓库 + 金额能力。历史查询也按当前访问权限过滤，不能因用户“当时有权限”而放行已撤销的权限。
- 保留 PostgreSQL 原生 RLS；替换的是 `auth.uid()` 等供应商身份绑定，不是删除行级保护。应用运行角色不是 superuser、BYPASSRLS 或业务表 owner；迁移 owner 与运行账号分离。
- 每次读写都在事务中，由服务端已验证会话设置事务局部身份上下文，事务提交/回滚后失效。数据库策略缺身份默认拒绝；不允许页面传 SQL、SET ROLE 或任意用户上下文。连接池复用、异常回滚和并发用户隔离必须专项测试。
- worker 使用独立的受限身份和已分配来源/仓库 scope，不以 superuser 通吃。金额表/估值查询另设受限授权，普通数量接口不能读取或返回成本；导出、缓存、错误和日志采用同样边界。

RLS 属于 PostgreSQL 原生能力；superuser、BYPASSRLS 与表 owner 的绕过行为需明确处理。[PostgreSQL RLS 官方文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 6. 历史能力是业务底座，不是复杂分析产品

从第一批新数据开始保存历史；不先覆盖最新值、日后再补历史。模型分为不可变来源证据、版本化业务事实、可重算日统计三层，详细粒度、唯一键、时间和修订规则见 [历史模型](history-data-model-v1.md)。

最低能力为：按日期/商品/市场/仓库查询库存、在途、可估值金额及数据质量；每个结果追到批次、身份/成本版本和计算运行。接口先服务验收与现有详情页，不新增趋势仪表盘。市场趋势首期仅指各市场库存/在途/货值分布，不等同销售或需求趋势。

V5 库存变化查询由历史统计读取可比快照及业务证据派生，不能写库存；货票状态历史复用货票修订。缺原因就明确未知，操作日志、货票邻近时间或相同数量不自动构成变化归因。

## 7. 数据迁移、备份与退出路径

1. **基线与依赖门**：先盘点真实 schema、扩展、函数、角色、Auth、对象和任务，再确定 PostgreSQL 版本与部署位置；记录现有测试缺口。只有得到具体环境读取许可后才核对远端，不使用历史发布报告冒充现况。
2. **隔离替代门**：在无真实外部写入的环境准备独立认证/权限/Repository 和新数据库基线；保留旧 UUID 与旧可售量含义。00001–00052 保存原件，不直接在纯 PostgreSQL 上盲目重放依赖 Supabase schema 的脚本；新基线记录每个旧表/函数/策略的去向和摘要。
3. **历史写入门**：新库存、映射、货票从第一笔即写历史与当前投影；业务提交和审计同事务。日统计失败不回滚已成功来源事实，任务留可重试水位；异常未完成的统计不发布。旧手动改量、入仓累加、脚本直写路径在目标系统全部收口。
4. **影子核对门**：旧系统仍是唯一生产写入方；新系统只接隔离快照/重放，不能同时跑两份生产调度。核对数量、状态、UUID、权限和历史重算；兼容的可售量逐行对比，新实物字段单独比对来源。
5. **受控切换门**：确认维护窗口、RPO/RTO、候选与回退版本；停旧写入/任务后备份 schema、业务/用户/权限数据、文件及引用、配置和同步水位。恢复演练、最终增量核对、登录与拒绝权限探针通过后，只启用新系统一个写入方。
6. **回退/退役门**：未开放新写入可切回旧入口；已开放必须停写、保存并对账新增量后再恢复，不丢历史。观察窗口和接受指标先约定；未验收或未单独批准不得删旧库、撤销旧环境恢复能力。

数据库备份、认证资料和对象备份均加密、限权，并验证恢复；单有导出文件不算可恢复。[PostgreSQL 备份与恢复](https://www.postgresql.org/docs/current/backup.html)

## 8. 验收与待决

- 必测：匿名/停用/三角色、空范围/跨市场/金额拒绝、会话与连接池隔离；同步重放/乱序/缺页/失败；映射重绑不污染历史；正逆到货顺序不重复计库存；历史补数/重算/权限撤销；无 Supabase 依赖运行与恢复演练。
- 历史模型验收场景见专篇；现有单元、lint/build、数据库并发/RLS合同和浏览器回归保留。新平台替换了旧测试前提时应迁移测试语义，不以删除测试制造全绿。
- 未决且阻塞对应实施：目标主机/数据库版本、认证组件与用户迁移策略、真实字段/来源完整性、日界线与陈旧阈值、成本口径、历史保留期、RPO/RTO。不会在本轮自动选择付费服务或清理历史。
- 下一实施合同：优先验证“独立 PostgreSQL + 认证 + 受限查询”的最小链路，再做商品身份/首仓历史快照；不按旧路线先在 Supabase 上扩建新模型。
- 本轮交接仅有文档和新规则入口；不继承前次 Demo 的推送/发布授权。生产、迁移、账号与主机操作另行授权。
