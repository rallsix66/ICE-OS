# ADR-ICE-001：商品身份、来源库存和方案隔离

> 后续决定：[ADR-ICE-002](ADR-ICE-002-independent-postgres-history.md) 已取代“继续默认保留Supabase”的平台方向；商品身份、来源权威和隔离边界继续有效。本文件保留初始决定，不证明迁移已执行。

- 日期：2026-10-13
- 状态：方案验证边界 accepted；真实模型与平台迁移 pending implementation approval
- 依据：用户 ICE v4 需求与本次明确实施授权；代码基线44d0b13。

## 决定

保留 UUID 和 Product→ProductVariant；以已有人工货号作为业务入口。新增外部标识/映射版本设计，不把所有外部 SKU 合并成全局主键。库存由 BigSeller/聚水潭快照决定，飞书管理货票业务状态，API只提供轨迹；到货/签收均不得自行增加库存。

不建立全新技术栈。本期用同一 Next.js 中完全隔离的虚构数据 Demo 验证六个视图；Supabase 和旧生产系统不动。未来自有后端/PostgreSQL迁移在现有封装后分批替换，保留身份/RLS等价约束。

## 原因和取舍

直接重写会丢失已经覆盖的仓库权限、并发和幂等保护；单SKU模型不能表达国家版本；把到货加库存会重复计算；只依赖最新总量差不能判断特定货票被吸收。使用独立Demo使产品决策不依赖真实授权，但它不证明生产权限和源可靠性。

保留旧系统意味着暂时并存历史字段/类型，迁移期间需要明确适配和新旧口径标签；不以保持兼容为由永久保留库存累加后门。

## 兼容、迁移和回退

本期不改schema和现役业务行为，撤回Demo路由即可退出预览。后续先确认主数据/来源，再新Migration关闭旧累加路径、增加映射与快照、影子核对后切读；不得改历史Migration。平台切换必须备份代码+schema+数据+身份+配置和同步水位，停写后回退，处理切换后增量，保留原备份。

## 验证门

Demo源依赖隔离、六视图和查找/详情、数量时间序列、缺成本不为零、未知不乱合计、映射五态和日志、角色视角说明、lint/build/默认单元测试。真实上线另需新角色/行列权限测试、重复/乱序/部分失败批次、部分到货/逆序事件、来源对账与恢复演练。
