### UI-1 商品库详情：固定商品，选择该仓 BS 商品

- 在现有“库存明细”里安排仓库绑定区，不删除其他页签，也不再增加独立绑定管理页。

- 更换时固定商品 A、仓库 W、原 SKU S1，搜索 W 内可用的 BS 单品，选择 S2。搜索覆盖该仓完整可选来源，不限未绑定、不限当前商品、不限列表当前页；支持 SKU 和原品名，包含已绑定和零库存。使用现有账号、参与范围内有真实来源的仓库，不擅自启用弃用仓。

- 替换成功后，S1 退出原关系、回到可待绑定的来源记录；S2 绑定 A。只动指定两条关系，不改 A 其他仓或同仓其他 SKU。
- S2 已绑定当前商品 A 时，只退出 S1 的关系，保持 S2 的现有关系和版本；不得因目标未变化报错，也不重复建立绑定。

2. 现有商品库库存投影及库存行不一定包含最新映射 ID/版本，不能直接拿历史批次里的 itemId 当当前归属。点编辑时按稳定来源身份读取当前关系，保存继续使用已有版本校验。
3. `inventory-detail-layer.tsx` 保存了打开行的状态快照，单独 `router.refresh()` 不保证当前抽屉更新；相关商品缓存及两个入口须一起核对。
4. 原待处理队列不能当作完整 BS 搜索，原批次数量也不能当导入后的新归属库存。一个来源键只处理一份当前关系，同名来源不能合并。
5. 国内当前读链和最新复核之间要确实接通；追加证据、刷新后回读与汇总必须一致，不能直接覆盖不可变历史。
