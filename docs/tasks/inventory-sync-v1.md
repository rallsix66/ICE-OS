# 商品库存与 BigSeller 自动同步 v1 开发任务

日期：2026-10-25。本文件保留原批准的完整任务合同（开工时 `INV_SYNC_V1_PLANNED`）。当前进度以[current-task.md](current-task.md)为准：2026-10-26 A1 主审独立复审 **`INV_SYNC_V1_REPAIR_V4_FINAL_A1_LOCAL_PASS`**；[独立报告](../../.local/inventory-sync-independent-v4-final-a1-20261026/independent-review.md)。A1 已关闭，B/C 保持通过，本轮技术开发收尾；BigSeller 单个数量及仓库编码口径已确认，正式对应整理和业务启用待落实。原执行自验及旧独审保留历史身份，不重开已关闭项。

本包要交付：系统自动下载 BigSeller 全部仓库的单 SKU 库存表，检查并保存各仓库存；用户能在数据同步页面设置频率、启停自动同步、立即同步和排查失败，在商品库存页面查看数量、来源时间及历史。人工上传可作排错备用，不能代替自动下载交付。

本包是一个完整业务交付，可以分内部步骤、跨会话接续实施，不在每个内部步骤重复要求用户批准或独立验收。不会因此扩成全 ICEOS 开发。现有商品库和飞书本地模拟接入继续保留原验收范围。

## 1 已确认的业务决定

以下来自本次用户确认，不再以“是否支持”反复询问用户：

- 日常库存必须自动读取。
- BigSeller 可以一次导出全部仓库，文件每行注明所属仓库。
- BigSeller 支持单 SKU 导出，可以不下载组合 SKU。SKU 指来源系统里的商品编码。
- 数据同步页面可保存自动同步开关、更新频率，并提供“立即同步”。
- 手动同步不改变原自动时间；手动、自动撞在一起只执行一次。
- 页面关闭后，后台仍应按计划执行。运行程序的电脑或服务器需要开机联网。
- 前端参考现有 `/demo/ice-v4`，最终以正确、可运行、可维护的实际结果验收；必要的数据和权限验证不能省略，不追求无关测试数量。

工程默认：首次配置自动同步关闭，频率预填 60 分钟；用户可改为整数分钟或小时，服务端统一保存间隔。初版下限 5 分钟、上限 24 小时，用于避免意外密集导出，不声称这是 BigSeller 的平台限额。实际平台限制更严格时显示原因并按实际限制处理。这些默认值可调整，不是已确认的业务时效承诺。

## 3 实现结构和资料入口

## 4 自动下载与文件识别

1. 绑定一个明确的 BigSeller 账号；读取并登记该账号可见的仓库清单。采集选择全部仓库、单 SKU、全部页，清除残留搜索、缺货、在售等会漏行的筛选。任何排除条件必须有明确记录。
2. 在 ICE 配置实际参与库存的仓库。默认候选为该账号发现的全部仓库；有明确身份及市场证据的可集中确认，缺失信息不猜。选择为空就停止发布，不能解释为所有仓库。以后新增仓库进入待确认，不悄悄扩展范围。
3. 每次任务固定账号、参与仓库集合和配置版本。仓库有稳定来源 ID 时使用 ID；只有名称时保留精确名称和限定范围，更名或歧义进入核对，不模糊匹配，不自动换仓。
4. 创建本次导出，等待生成完成，下载到本次任务专用位置。保存导出任务标识；来源不提供标识时，以本次操作、完成事件、下载响应和文件证据建立可核验对应。不能扫描下载目录取“最新 Excel”，也不能沿用以前的导出任务冒充新采集。
5. 文件按真实表头读取，不固定列位置、行数或现有 530 行哈希。保存文件指纹（用来核对内容是否相同）、解析版本、行数、仓库覆盖、任务号、时间和原始行位置；只有真正空白行可忽略并计数。
6. 下载超时、登录失效、文件损坏、表头缺失、意外组合表内容、来源身份不符要返回可理解原因。重试次数和等待有上限，不能无限重登或反复创建导出任务。
7. 每次独立、真实的新导出，即使库存数量未变化，也记录新采集并可更新成功时间；同一任务重试只认一次发布。文件指纹不能单独充当采集任务号。旧文件重放不能刷新真实成功采集时间。
8. 来源提供库存观测时间时保留；没有时明确标为本次采集时间，并保存导出开始、完成及下载时间，不伪造精确的库存发生时间。

用户已确认全仓及单 SKU 导出能力；现场验证用于接好按钮、下载文件和当前账号权限，不再单独发起一轮业务可行性批准。

## 5 自动与手动同步规则

### 设置与计划

- 数据库保存来源账号、参与仓库、启停、间隔、计划基准时间、下次执行时间和配置版本；页面刷新及进程重启后仍保留。
- 按固定时间执行。例如 10:00、10:30、11:00 自动运行，10:12 手动运行后，下次仍是 10:30。首次启用、重新启用或更改间隔时，以保存时刻建立新计划，下次为保存时刻加间隔；页面显示结果，用户要立即读取可点“立即同步”。
- 同一账号同一时刻最多一个活动任务，包括排队、下载、检查、发布及结果未知核对。限制必须在服务端和数据库成立，不能只靠禁用按钮。
- 自动与手动同时触发时，返回同一活动任务，不额外排队补跑。任务跨过自动时间点时，记录该时间点已由正在执行的任务覆盖，自动时间继续前进。
- 关闭自动只取消以后自动触发，当前任务继续按开始时的配置执行；手动同步仍可用。修改频率不改变当前任务。调整仓库范围不扩展当前任务；发布时必须再检查授权和仍允许发布的仓库，移除/撤权的仓不能继续发布。

### 后台在线与恢复

- 页面显示后台在线、离线或最后联系时间；服务器停机/休眠不宣称仍在采集。关闭业务网页不能停止后台。
- 任务领取、执行凭证和后台存活时间持久保存。超时接管时，旧执行者即使恢复也不得继续发布，避免两份结果竞争写入。续期、写任务结果、释放占用和发布库存都要核对当前执行凭证，旧执行者不能修改接管后的状态或释放新执行者的占用。
- 重启后先核对未完成任务是否已提交，再恢复；错过的多个自动时间点最多合并一次当前读取，不密集补跑，不伪造停机期间历史。自动关闭时不新增错过时点的补跑；已存在的自动或手动任务仍先核对已提交结果，再恢复未完成阶段或明确结束为失败，不能长期卡在活动状态。关闭自动不撤销已有任务。
- 下载或解析确定失败，可有有限自动重试并记录原因；登录需要人工恢复时停止反复尝试并提示。手动重新同步创建新的读取任务，不改变自动计划。
- 数据库提交后断线属于“结果待核对”，保留原请求号及输入，先查回执，再决定恢复；不能直接当失败另建批次。只重复核对同一请求，不重复写入。

## 6 商品对应与库存保存

### 商品身份

**2026-10-26 用户补充确认（晚于 A1 验收）**：BigSeller 库存数量均按单个商品计数，不是箱，不做装箱数换算；其他国家仓商品编码对商品库“69编码”，菲律宾新创启辰仓主要用货号、少数条码可参考库存辨认。规则唯一正文见[商品身份标准第7节](../product-identity-standard-v1.md)。数量单位已确认，不再作为业务待决；WM0026 该仓两种编码已确认同时展示，各自数量保留、不强制二选一；本次未决定正式合计口径，不阻塞其余明确项。本次只记录规则，程序、数据库验证标记、正式对应与页面入口尚未据此修改；下面验收时的“单位待确认”保留为历史记录。

现役 `catalog.catalog_item` 承担商品主实体，保留其 UUID。新增或落实稳定 Variant 层，Variant 指同一商品下可区分的规格、市场或销售单位，库存通过它关联商品；不为了表名再复制一份商品主库，不按仓复制商品。旧 `public.product/product_variant` 如确需兼容，必须显式关联，不能按货号/名称碰撞当作同一 UUID。

来源对应键至少包含系统、账号、仓库和外部 SKU，市场/单位按有证据的规则保存。来源编码与69编码保持字符串，不丢前导零。关系保留状态、版本、理由、操作者和时间。

既有 BS 人工决定可显示为有出处的建议，管理员按已确认的单个数量口径及仓库编码规则核实适用账号、仓库和商品后集中明确确认；不能默认全选采用或自动升格为永久关系。已确认且没有漂移的关系后续自动沿用，不要求每次重选。新增、歧义、规格/单位明显变化进入待核对，不猜绑，不自动建新商品；商品建档沿用商品库。

未对应记录保留原始数量，但不计入商品合计，且不阻塞格式完整的仓批次保存。关系重核或停用后立即退出当前商品汇总；换绑和重新确认形成新版本，等下一次完整读取发布后使用。旧批次仍按当时关系和资料版本展示，本包不做历史重述。

确认、重核和停用要带上操作者看到的旧版本，防止覆盖别人的更新。库存发布事务再次核对采用关系仍有效、版本未变、Variant 商品归属和单位仍适用；期间发生变化时拒绝按旧计划发布，返回重新核对，不让排队中的任务穿透已发生的停用或换绑。

### 数量与批次

- 分别保存现有库存、订单已锁、整仓可用、活动预留、来源在途。现有库存和可售量不能互相冒充，来源在途不计入飞书物流在途，也不加进实物库存。
- 数量是当时余额：100 更新为 80 后应为 80，不能累加成 180。拒绝无依据的单位换算；商品归集必须使用相容且已确认的单位。
- 明确 0 才是零；空值/错误分别处理，不使用 `int_or_zero`。关键编码、仓库或数量解析失败不能静默跳行；同仓同 SKU 重复不能随意求和或保留第一行。
- 同商品不同仓分别保存。相同仓库存在两个来源覆盖时先解决权威来源，不能叠加重复覆盖。
- 按完整仓发布：仓内事实、当前批次指针和成功日志在同一个数据库事务里完成，即全部成功或全部不生效。已发布事实不可覆盖或删除，后续更正追加新批次。
- 同一导出文件中的独立完整仓可分别成功；失败仓保留上一成功批次。整次任务显示“部分成功”及逐仓原因，不允许把部分成功显示成全仓成功。涉及账号、文件结构或整体覆盖的错误阻断整个文件；某仓可明确定位的错误只阻断该仓。
- 只有本次固定范围的所有仓库完成有效发布，才更新该范围的“最后全部成功时间”。范围变更后不能继承旧范围的全绿状态；每仓成功时间独立展示。
- 缺仓不等于空仓。空仓需要导出范围及来源空仓语义证明，不能根据“文件没有该仓行”清零。缺 SKU 不补 0，不把上期行拼进本期；可在详情另示“本次未见、上次已知数量”，不放入本期合计。
- 同一任务同一仓同内容重试返回原回执；同任务异内容拒绝。旧观测不得倒退当前指针，同时间冲突无可靠顺序时待核对，不能最后写入者获胜。
- 保存当时商品/Variant/对应/仓库及单位版本或等效的不可变证据，商品改名和仓库变更不能改写历史解释。当前值从已发布事实派生，不开放手工改数量。

最低数据职责为来源设置与范围版本、同步任务与逐仓结果、原始文件证据、Variant 与关系版本、不可变库存批次和行、当前指针、请求回执与审计。可复用现有合适表；不得把这些职责简化成覆盖旧 `inventory.quantity`，也不新增第二套统计事实库。

## 7 页面交付

### 数据同步 `/dashboard/sync`

- BigSeller 显示真实账号标识、参与仓库、自动启停、频率、下次计划、后台在线情况、登录状态和“立即同步”。敏感会话内容不进页面。
- 状态至少区分等待、下载、检查、保存、全部成功、部分成功、失败、结果待核对和需要登录；提示下一步怎么处理。
- 显示最近尝试时间、每仓成功时间、当前范围最后全部成功时间，不能用下载成功替代库存成功。
- 可查看任务详情、各仓行数/采用/待核对情况、错误原因与来源记录；提供重新同步、原请求结果核对，以及必要的商品对应复核入口。技术 UUID 不作为主要业务文案。
- 确认关系可集中操作，显示仓库、外部编码/名称、建议商品和证据，明确哪些行将被采用；已确认关系的重核/停用可维护且留历史。
- 飞书商品资料保留现有本地快照入口及真实状态；与尚未接入的“飞书物流表”分开。聚水潭、飞书物流、喜运达本包显示未接入，不放可点击却不起作用的启停或同步按钮。

## 8 权限与运行维护

沿用当前已启用的管理员访问边界，本包不顺带开放负责人/运营整套权限。配置、立即同步、关系确认、任务详情和原始文件访问均需服务端验证会话、启用状态及相应范围；后台仅有其来源/仓库范围内的必要写入权限，使用 PostgreSQL RLS（数据库本身的行级访问限制）。运行账号不得为表 owner、superuser 或 BYPASSRLS。

库存列表、详情、历史及导出同样验证服务端身份和范围，不能只保护写操作。普通库存查询只返回业务需要的数量与身份字段。导出表可能有价格，公共原始行、错误、日志和接口按白名单剔除金额；完整文件保存于受限位置，不能放 public 目录。业务页面默认只提供去金额明细，如开放含价格原文件下载，必须另验现有金额权限和数据范围，来源管理权限不能代替金额授权。登录会话、下载文件、真实样本与原始证据不入 Git。

交付一个可复现的本地运行入口，能启动独立数据库/网页/后台、查询状态、停止本包自己的进程，并支持重启恢复；使用现有准备工具时先确认实例归属，不能覆盖 3011/3021/3022。后台与网页均使用同一候选版本和配置。需要新增运行依赖时锁定并说明，不安装无关框架。

运行说明须覆盖：首次登录和登录失效恢复、启停/频率/范围设置、失败排查、后台离线、数据库和文件备份恢复、证据位置、如何仅停本包进程。只做一次本包数据及回执的备份恢复验证，不重做整个旧平台灾备工程。未确定保留期前不自动删除库存历史和原始凭据。

本地运行通过不等于已部署常驻服务器。生产主机、自动开机、生产账号与数据库切换另行安排，不把用户关闭网页不影响同步误写成电脑关机也能同步。

## 10 验收标准

所有必需能力都要完成；证据按真实账号只读采集、隔离数据库演练、既有可信证据分别标注。无需为了制造库存变化去修改真实 BigSeller，变化、缺仓和故障可由真实格式的标注副本演练。

| 检查 | 最低通过结果 |
|---|---|
| 自动读取 | 至少一次从已确认账号自动发起全仓单 SKU 导出、下载新文件、逐仓校验并保存到独立实例；选定仓库覆盖可解释，页面能追到文件行 |
| 真实定时 | 保存频率后，无需打开业务页面，后台在到期时自动执行；设置、下次时间和结果重启后仍存在。短间隔只在隔离调度验证使用，不对真实平台密集导出 |
| 手动和重叠 | 立即同步有效且不改变自动时间；双击、两个页面、自动同时触发只形成一个活动读取任务；暂停自动仍可手动 |
| 重启恢复 | 中途停止本包后台再恢复，不丢结果、不密集补跑；过期执行者恢复后无法发布；恢复不要求重建数据库 |
| 文件正确性 | 表头重排仍按含义读取；损坏文件、关键字段错误、同仓重复 SKU、错仓/缺仓不静默采用；零、缺值与空仓有不同结果 |
| 更新与历史 | 100→80 结果为80；旧批次可查；同任务重放不新增发布；两次真实新导出内容相同仍可登记新采集；旧文件不能假刷新成功时间 |
| 部分与未知 | 一个仓失败保留该仓旧值且标部分成功，不刷新全范围成功时间；提交后响应丢失按原请求找回唯一回执 |
| 商品对应 | 未对应不进入商品合计；明确确认后由新批次采用；重核/停用立即退出当前汇总；换绑不改旧历史，不复制商品 UUID |
| 页面与权限 | 同步→库存→详情→来源历史完整操作可用；列表详情一致；匿名/停用/无动作或范围权限被服务端拒绝；不泄漏价格和会话 |
| 可维护 | 使用交付说明能启动、停止、登录恢复、定位失败，并恢复一次本包数据库和必要文件；原现役实例与证据未改写 |

检查重点是错数、错归属、漏数据、重复发布、历史丢失、越权、必要功能缺失或关键流程不可用。非阻塞美化另列，不为它们反复返工。正常使用有明显卡死或无法操作要修，不重开旧 15×20 性能门禁。
