## 2. 已交付能力

### 2.1 自动读取、来源新增/修改/删除、失败保留旧数据

- **定时读取已启用**：`scripts/shipment/worker.mjs` 每 10 分钟按数据库计划读取飞书 wiki「物流情况表」（sheet `b42d8b`），与页面「刷新来源」共用同一读取/解析/入库链路和读取租约，手动与定时不并发读同一来源；后台运行身份为受限的 `ice_p0_02_sync_runner`，不依赖浏览器登录，读取人/操作者记 NULL。
- **新增/修改**：来源新增票或明细按稳定键入库；原票补/改采购单号、运单号可延续原票（身份不唯一时标「身份待核」，不静默新建、不清除人工关联）；内容有变化写入修订历史；内容哈希未变返回 `unchanged`。
- **删除（本次来源未见）**：新快照中没有的票/明细退出当前列表与计数、不进入搜索与货值，但历史行、绑定与「本次来源未见」说明保留，数量不改写成 0、不当作到货。
- **失败保留旧数据**：读取失败只写失败快照（错误码/原因/时间），不写业务数据；页面继续显示上一份成功数据及来源时间，物流页失败只留一句原因 + 「查看同步」，下次计划自动重试；旧数据不会因一次失败被清空或覆盖。
- 页面顶部与数据同步页显示：最近成功读取时间、最近尝试、下次计划、失败原因；已打开页面每 20 秒只读探测新结果并原地刷新，不触发飞书读取。

### 2.2 商品绑定与已确认对应复用

- 明细可关联 ICE 商品（按货号/名称/条码搜索），保存后写审计（操作者、时间、方式）并逐条回读；可更换或清除，历史保留。
- 自动关联只做**明确唯一**：规范化品名与商品库标准名完全一致且只命中一个商品才标 `auto`；其余保持未关联，交人工确认。
- **已确认对应复用**：`catalog.shipment_product_mapping`（来源 + 规范化品名 + 市场 → 商品）保存 15 条已确认对应；保存绑定时可勾选「后续同来源、同品名、同市场沿用此对应」（默认不勾选）；后续读取只对本次仍在来源、从未人工绑定/清除的明细采用，人工绑定/清除与未确认市场/多版本冲突保持不动。
- 编号变化延续原票时绑定不丢（挂在明细 UUID 上）；来源移除的历史明细保留原绑定但不参与当前查询。

### 2.3 人工修正在途、装箱数换算、冲突复核

- 货票详情每条商品明细可「修正在途」：运输中 / 已到货待上架 / 全部已上架 / 分批上架（填累计已上架，替换不累加）/ 状态未知；保存前显示将采用数量与算式，保存后明细、票级有效状态、列表与市场货值立即更新。
- 人工修正保留飞书原文并标「人工修正 + 修改人 + 时间」，可「恢复按原表判断」，全部动作写入人工修正历史；普通定时读取保留人工结果。
- **装箱数换算**只取商品库 `cartonQuantity`（不从 200ml/120g 等规格推算），显示「箱数 × 装箱数 = 商品数量」；缺装箱数仍可直接填商品数量。
- **冲突复核**：原表改发货量或累计到货与人工修正矛盾时整批照常读入、保留人工记录与历史，受影响明细标「待复核」并显示旧发货量/新发货量/之前确认上架量；矛盾未解决前不计入货值，在「修正在途」重新确认后恢复。页面没有同票同商品多条明细的现役自然样本，该口径由单测与只读 RPC 事务探针覆盖。

### 2.4 拆合票提醒与人工处理

- 每次成功读取后，用**相邻两次成功读取的飞书原始分组**对照检测拆票/合票；归属一变就提醒（即使第二张票以前出现过、同拆法以前确认过），同一次变化至少提醒一次、连续同分组不重复提醒。
- 入口：物流在途工具栏「待复核」+ 本页弹窗；并排显示上次/本次单号、市场、商品、数量，四个结论（仍是一票 / 已经拆开 / 已经合并 / 恢复按飞书判断）；关闭弹窗回到原市场/筛选/页码，零待办也可打开查看历史。
- 保存人工决定后只把「本次复核涉及、能明确对应」的原明细绑定带到目标明细（行范围 + 品名/数量两侧一致 + 商品唯一），记 `manual_selected`、操作者与依据；范围外或已有绑定一律跳过，无关新票即使同品名同数量也不继承。人工覆盖只控制展示/计价，不遮住后续来源变化；可恢复为按飞书判断。
- 已验证克隆库流程「一票 → 拆两票 → 合回一票 → 再拆两票」每次都提醒；现役只保留 R12 的一条历史合票 resolved，pending 0、active override 0。

### 2.5 单票、市场、商品货值及商品库关联货票

- **单票**：货票详情头部/状态区显示「本票在途货值」（全页仅一处），按逐条剩余在途 × 采用进货价复算；9258750 同一次成功读取为 **¥124,132.80** = 唇泥 ¥94,432.80 + 腮红 ¥29,700.00。
- **市场货值**：「货值汇总」与「货票列表」共用同一市场范围；全部市场按市场一行，点市场看商品/采购单/原票与「未计入明细」；票数/明细数/金额口径一致，搜索后切汇总不再出现「共 1 票对四市场总额」。
- **商品**：商品库详情第四页签「关联货票」按绑定商品 ID 汇总当前在途（市场、采购单号、运单号、物流情况、本品发货量/累计已上架/剩余在途，点行打开原票）；概览「在途库存」卡片接同一份数据，有待核时标条数，全部待核显示「待核」，点进页签看市场小计与组成采购单。
- 数量与状态复用物流在途最终采用结果（人工修正生效、待复核排除、冲突不计入）；一票多款只取本品、一票多运单只算一次、无采购单号票也可打开。
- 单位成本复用商品库现有读取链（`read_item_amounts` → 采用进货价，不含运费），未绑定「—」、缺价「成本待补充」，不写 0、不冒充已确认币种/计价单位。

## 4. 已知限制（集中登记，只写这一次）

1. **浏览器前进不自动重开库存详情**：库存列表关闭详情后按浏览器「前进」会回到详情地址，但弹窗不会自动重新打开（修复前既有行为，R16 未扩大范围）。
2. **商品单位资料缺失**：现役 126 个商品的「单位」字段全缺失，页面显示「单位 待确认」；不从 200ml/120g 等规格猜支/瓶/盒，装箱数换算只认商品库 `cartonQuantity`。
3. **长期运行稳定性尚未验收**：自动读取尚未做多日/多周连续运行、崩溃恢复、时钟漂移、来源长期变化等稳定性验收；读取进程没有服务守护自动拉起，崩溃需用 `start-worker.mjs` 重启（状态脚本会显示未运行）。
4. 其他边界（沿用各轮结论，不重复验收）：
   - **喜运达轨迹按用户决定暂缓**；**库存自动同步恢复属于另外的工作**，本板块不启用库存同步 worker、不触发库存同步。
   - 拆合票检测/沿用依赖身份匹配与原明细归属：身份不唯一、整体改号、大量同时插入或同时改量时保守跳过。
   - 聚水潭没有导入成功时间记录，同步卡按需求显示「暂无记录」。
   - 商品单位成本的币种/计价单位资料仍为 unknown，按商品库现有「采用进货价」口径显示，不含运费。
   - 未做完整权限矩阵、真实撤权、200% 缩放与金额权限拒绝负样本。
   - 飞书授权依赖本机 `lark-cli` 与系统凭据库；授权失效会影响读取，但不影响已有数据展示。
   - 只在本机本包/当前实例通过；**未推送远端、未合并、未正式部署、未做长期运行验收**，不等同于整个 ICEOS 验收。
