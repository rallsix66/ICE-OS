## 1. 本包要交付什么

在本机日常入口 3011 完成可运行、可维护的三个页面：商品库以查改资料和来源身份维护为主；商品库存提供默认「仓库明细」和「商品汇总」；数据同步突出运行状态、逐仓结果和必要操作。国内数量使用之前已冻结的聚水潭表格快照，明确日期和原表口径。

这是一个完整交付包，可在内部按依赖分步实施、跨会话接续；不要只交方案、静态稿或其中一个页签就停下。只在实际缺少输入、真实业务歧义或超出本合同的权限时集中说明问题，其余授权工作继续。

用户已确认的核心要求：

- 商品库负责商品信息；商品库存同时满足逐仓查全部 SKU 和按标准商品看各市场分布。
- 仓库明细**产品名称为主，来源 SKU 为辅**；每行仍是来源账号 × 仓库 × SKU，不按名称合并。
- 不同人员未来按数据范围、动作、金额权限看到不同内容；本包不把未来多角色做成演示切换，不扩建权限平台。
- 国内库存先按旧表展示；数据同步界面由执行方按下面确定的职责优化。
- 以最终正常使用、数量正确和可维护为验收重点，复用可信证据，不反复重跑无关套件。

## 3. 页面职责与界面结果

### UI-01 商品库：资料优先，只有一处正式库存对应维护界面

- 主表突出名称、图片（缺图用现有占位）、ICE货号、条码、规格/单位、必要资料状态。按现有金额权限保留必要价格资料，库存及货值不再占据主表中心；库存可简要提示并定位到库存页。
- 保留查资料、编辑、修订历史、现有来源查看及错误恢复。优先复用现有商品详情：商品库打开默认「商品资料」，库存打开默认「库存明细」，不复制第二套主资料编辑器。库存独有的未对应行无需伪造商品详情。
- 商品库承载一个「来源 SKU 对应」维护入口。库存与同步页保留定位链接，带上商品/仓库/SKU及返回上下文；复用现有待核队列、已确认关系列表和动作，不重新实现确认/重核/停用/换绑机制。处理后回到原筛选与位置。
- 本包统一的是 **BigSeller 正式库存对应操作**。旧 BS/JST 样表「本批采用」、飞书商品资料来源、BigSeller正式对应分别标清，不合并资格。已有 `/dashboard/catalog/sources` 飞书商品来源更新功能不被新入口覆盖。
- 保留对应版本、操作理由、服务端权限、原请求结果未知核对、他人请求隔离、确认后等待下一完整批次采用等现有含义。迁移旧入口须兼容跳转，不留失效链接。

### UI-02 仓库明细：默认视图，名称主、SKU辅

- 「仓库明细 / 商品汇总」在同一库存入口切换。默认仓库明细；URL可还原视图、来源范围、搜索、市场、仓库、分页和所开详情，刷新/前进后退/关闭详情不丢上下文。不强制新状态库或缓存平台。
- 名称/规格为第一视觉层，ICE货号及来源SKU为次要文字，SKU支持复制，商品名称/货号/条码/来源SKU可搜索。已确认正式对应优先标准中文名称；未对应显示**来源名称**并标待确认归属，不把建议商品名当确认结果；来源名称缺失才用SKU及明确缺名提示。
- 主要列：商品、国家/仓库、实物库存、可售库存、数据状态；来源时间可在状态区域紧凑呈现。锁定/预留/来源在途和原始出处在详情中可查。切到单仓后仍能明确当前仓，不要求重复宽列。
- 全部参与仓的有效单SKU来源均可查：已对应、未对应、真实零库存、同商品同仓多个来源编码不丢。全部参与仓不等于账号下弃用/未选择仓库；市场未知保留「市场待确认」，不猜归属。
- 简短异常状态可点击看具体仓库、SKU、数量、原因；不把长说明铺满每行，也不只剩一个无内容的感叹号。失败旧值显示旧时间，本次未见/无成功数据/无权限/读取失败不能写0。
- 国内表格用独立来源范围和「国内 · 原表未注明仓库」表达，见 UI-04；不是伪造 BigSeller 国内仓。

### UI-03 商品汇总：一标准商品，各市场对照

- 主要列为商品名称/货号、国内表格数量、现有海外各市场实物数量、简短状态。默认实物口径；可售等其它口径先沿用详情，不为本包再造指标切换框架。未知市场另列/明确提示，不能塞入某个国家或从对照中消失。
- 点击某市场数量可定位同商品同市场的仓库明细；明细里的已对应商品可反向定位商品汇总或商品资料；返回恢复原视图和位置。
- 本包采用正式页现有筛选语义：选择市场/仓库后，显示范围与计算范围同时收窄，标题明确范围；全部海外时显示市场对照。国内列只在包含国内的来源范围显示。不能照抄 Demo 的「筛商品但仍算全部市场」语义。
- 商品集合包含本范围有库存/对应/关联待核线索的现有标准商品，以及本次国内快照有已核对关联的商品；没有BS记录但有国内来源的商品不能漏掉。没有标准商品归属的来源记录不伪造成新商品，提供可定位的未纳入汇总提示。
- 每格按完整筛选范围而非当前明细页计算。只有允许归集的有效来源进入商品合计；未对应、待下一批采用、重核/停用及同仓双编码待合计保持原语义。双码不能默认相加、只取最大/第一条或因一条为0而消除待核。
- 国内与海外不同时间、不同口径，不提供伪装成同一时点的全球总库存。不给所有不同产品凑一个没有业务意义的总数量，不新增货值、低库存阈值或周转结论。

## 4. 数据读取与权限合同

这是有限读取适配加界面调整，不是纯CSS任务，也不是重做库存后端。

- BigSeller仓库明细以**每仓最后完整成功发布批次**为底稿：复用 `inventory_warehouse_state.last_batch_id` 及现有仓库读取状态，读取该批已采用和未对应有效来源行，关联同批 `run_id + excel_row` 取得原始名称等字段。不能拿 `read_inventory_catalog_sources().sourceRows` 的「最近登记run」直接冒充当前完整批次，它可能尚未成功。
- 来源原数量和是否计入商品汇总是两个独立信息。行上归属/采用状态须依据当前对应及该批历史含义如实展示；重核/停用不删除原来源事实，不把原数量再次计入商品合计。坏行/重复等进入问题详情，不能当有效库存条目补0；出现遗漏须解释所属状态，不能只比较行数。
- 失败仓沿用其上次完整成功数据和时间；新成功批次未出现的旧SKU沿用现有「本次未见」说明/上次已知值，不把旧数量混为本次现值。明细来源必须能回到批次，不能混拼失败新文件与成功旧批次。
- 商品汇总继续复用服务端现有有效库存/待合计/单位/覆盖规则。列表、详情、商品库引用的库存同范围同批次一致；允许新增必要的分页明细读取和按市场批量投影，不另写页面加总、不回退旧BS样表或旧 `inventory_current` 投影。避免按每行/每市场重复读取整份上下文，保留刚通过的响应速度成果。
- 当前真实权限仍是启用管理员；新只读入口、国内快照及迁移后的维护页均继承它，输入在真实入口校验，不让浏览器读取原私有文件。现有金额能力保持原样，本包库存DTO不新增金额。
