# ICE v4 数据流与对账合同（v2）

> 最新平台目标见 [architecture-v3.md](architecture-v3.md)，历史扩展见 [history-data-model-v1.md](history-data-model-v1.md)。本篇四源权威与正逆序边界继续有效，目标存储/认证不再依赖 Supabase。

## 新增历史链路（设计，未实施）

来源输入 → 保留业务/观测时间与系统接收时间 → 完整性与身份校验 → 同事务追加不可变事实/业务修订、当前投影、日志和持久化统计待处理记录 → worker 生成候选日统计 → 原子发布统计版本 → 按当前授权返回历史DTO。

- 统计失败不撤回成功来源事实，不发布半份统计；重试使用输入清单/版本幂等，不依赖内存回调。
- 迟到、更正、映射/成本重述会生成新历史修订并重算受影响日期及后续沿用区间，保留旧结果。当前值、当时记录和修订后解释分开。
- 日统计带日历/时区、业务截止/知识截止、质量/覆盖与批次/版本证据；未知不补零、未来快照不填过去、余额不跨日期求和。
- 脱离Supabase时保留UUID和历史证据链；没有证据的旧日期不补造，现有最新可售量不得转换成历史实物库存。

## 四个来源各自负责什么

- **聚水潭**：未来国内库存完整快照源，决定国内实物/可售数量。发货造成的减少由其下一有效快照体现，DIS 不因飞书发货再扣减国内库存。目前未实现接入。
- **飞书物流表**：未来货票、商品明细、数量、人工业务状态和修订版本主源。发货/部分收货/到货必须能追到稳定记录 ID 和明细 ID；当前人工 Shipment 不是已接入飞书的证明。
- **喜运达 API**：外部物流轨迹证据，只更新外部事件与同步状态；不能推进飞书业务状态、提供或推断商品清单、修改明细数量、增加库存。已有轨迹/绑定基础，不等于 v4 多账号模型已经实现。
- **BigSeller**：海外库存完整快照源，决定海外实物/可售数量；下一成功批次体现真实库存。抓取器已有 current/locked/available/transit 原始值，但当前 `inventory.quantity` 实际仅保存 available，不得改标签冒充实物量。

来源账号、仓库、市场、业务时间、采集时间、原始键、批次与版本均独立保留。BigSeller 来源在途仅为观测/对账字段，不与飞书在途叠加；API 的 delivered 不等于飞书“已到货上架”。

## 采集、身份解析与发布

1. 适配器接收来源输入，记录 `source_system / source_account / source_scope / batch_id / source_version` 和业务时间、采集时间。不得把缺失账号默认为另一账号。
2. 校验分页、仓库范围、行数/重复键、字段类型和批次完整性。原始零、缺失值、解析失败分别保存；半页数据或解析失败不能发布为新库存，更不能把缺失 SKU 自动归零。
3. 使用来源系统+账号+国家/仓库+外部 SKU 查**已确认且有效版本**的映射，定位 ProductVariant UUID，再归集 Product。公司货号和69编码用于查找/复核，不替代技术主键，也不自动合并同名产品。
4. 原始明细可保留未匹配数量；未匹配、待确认、重新核对、停用映射进入异常区，不能进入已确认商品合计。历史快照固定当时映射版本，换绑不得重写历史。
   当前读模型还要验证最新有效映射状态及版本；重核/停用立即失效当前归集，换绑后待新完整快照或受审计的版本化重新解释，不能利用旧快照的confirmed状态继续归集。
5. 完整批次在单事务内保存不可变快照、成功发布标记、最新有效指针和操作日志。幂等键防重放；旧批次可留档但不得倒退最新指针。只有发布成功才更新成功时间。
6. 授权读模型分别输出数量、来源、时效、映射/对账状态、估值覆盖范围；读取和渲染不得反向触发同步或修改业务状态。

## 正序：发货 → 运输 → 飞书到货 → 新库存快照

下面只跟踪同一海外仓的一个虚构商品、同一票100件货。起始实物快照240件；示例假设无同期销售/调整且收货证据明确，不代表实际同步必然正好增加100件。

```text
发货/运输：   海外快照240 + 飞书剩余在途100
飞书到货：   海外快照240 + 飞书剩余在途0，收货100待快照确认
新完整快照： 海外快照340 + 飞书剩余在途0，收货证据与该批次已核对
```

- 发货先形成/更新飞书货票和版本；聚水潭快照未更新时，国内仍显示旧数量及时间。国内库存与在途可能重叠，跨阶段总量/总货值标“待核对”，不伪造国内扣减或资产守恒。
- 运输节点来自 API，仅追加来源轨迹；飞书状态与 API 状态并列，冲突显示而非自动选“更靠后”的状态。
- 飞书确认到货时，只有明细到货数量完整、合法且可追溯，才将对应剩余在途减为0；保留业务收货事实及“待快照确认”提示。
- 该时点海外库存仍为240，不能手工加100，不能把待确认收货100再包装成另一笔可加库存。显示240并不宣称货物损失，也不宣称整体资产从340降为240。
- BigSeller 新完整批次发布后海外库存更新为来源给出的值。本例为340；真实值可能因销售/调整不同，必须按实际快照展示，不能强制改为340。
- 仅“有新快照”不等于证明特定货票已吸收；需收货证据关联完成后才关闭该票待核对状态。

## 逆序：库存先更新，飞书仍在运输

若海外快照先从240变为340，而飞书仍有100在途：**不能展示440为去重总量，也不能仅凭增量100就宣布这票已收货。** 差额可能来自退货、调整、另一票收货或多种变化相抵。

- 库存340和飞书在途100可分别显示，但加总指标返回不可确认/待核对，不静默归零在途、不提前更新飞书。
- 目标 `receipt_evidence` 是待批准的最小对账实体：`shipment_item_id`、`snapshot_batch_id / snapshot_id`、`source_receipt_key / source_version`、`confirmed_quantity / effective_at`、证据方式与确认人/时间；`evidence_status` 区分 pending/confirmed/rejected/revoked，撤销追加版本而不删除旧证据。
- 自动关联须有可信来源收货标识及数量对应关系；没有来源收货接口时，可由授权人员根据外部凭据明确确认并留痕。库存 delta、抓取时间先后和 API 签收都不能单独成为该证据。
- 证据只使去重/待核对判定可信，不改变来源库存、不代替飞书状态；后续飞书到货更新消除同一数量在途时，不能再次减库存或撤销已发布快照。
- 证据缺失或冲突时保留两条原始事实和差异；不提供貌似精确的可加总数量或总货值。人工确认权限和证据格式需另行验收后上线。

## 部分收货与明细一致性

- 收货以货票**明细**为单位：`剩余在途 = 有效发货数量 - 有效累计到货数量`。数量不得为负，到货不得超发；重复回传累计60不能再增60。
- 发100、到60时，在途40；旧海外快照仍240，另显示60待快照确认，不相加得到340。若新快照为300，也不能仅据差额认定这60已被吸收。
- 一票多 SKU 分别记录映射和累计收货，不能用票级“已到货”填补缺失明细数量。飞书状态与明细不一致进入复核，不悄悄补齐或归零。
- 正式去重合计须满足相关来源时效、完整性和收货证据条件；部分收货的已吸收部分与仍在途部分分别关联，不能按整票一次性吸收。
- 发货数量更正、拆单、取消、退货保留新业务版本及原因；不得通过改小发货数量隐去已收货事实，冲突先冻结该明细自动归集，库存仍等待各自来源新快照。

## 运单绑定和轨迹

目标唯一候选键为 `物流商 + 来源账号 + 运单号`，再核验仓库/市场；内部绑定保存 Shipment UUID，不以不唯一的采购单号、SKU 或商品名称代替关联键。

- 缺账号、同号多候选、仓库/国家冲突、历史已绑定均进入待绑定/待复核。没有足够范围信息的原始记录只对授权审查人员可见。
- 一票多运单允许分开显示各段轨迹，但只有明确关联才能挂到同一票；一张运单对应多票的分摊若来源未证明，不按数量/名称猜分配。
- 重绑需权限、预期旧版本、理由及操作日志；不得因为一次新抓取而覆盖人工已确认绑定。旧证据关联仍可追溯。
- 运单保持稳定的外部记录UUID（provider/account/waybill身份），绑定修订另存。轨迹幂等键关联稳定运单，而不是每次重绑的新修订ID，避免换绑导致重复摄取；事件发生时归属仍保留修订证据。
- 事件按来源稳定事件键幂等；没有稳定键时使用确定性原始字段指纹。缺业务时间不得以“本次抓取时间”伪造发生时间并导致重复事件。
- 乱序轨迹按发生时间呈现、采集时间另存；旧节点不能倒退业务状态。未知状态、异常、来源撤回均保留证据，不自动当作最终到货。

## 重放、乱序、撤销与失败保留

- **重复输入**：同源同账号同版本/批次重试返回已有结果，不重复创建货票/收货/快照；重复请求日志与原请求串联。
- **旧版本到达**：保留接收记录，标陈旧而不覆盖新业务状态/最新快照。相同版本不同内容视为冲突，不能“最后写入胜出”。
- **合法撤销/更正**：以新版本、操作者和原因记录，重新计算有效在途/对账状态；不编辑历史快照，不向 inventory 发反向增减。涉及已核对收货的撤销触发重新核对。
- **同步失败/部分失败**：保存失败批次和可诊断分类，不发布失败数据；界面继续显示最后成功快照、成功时间和失败时间，不能更新成功时间或清零。
- **成功但陈旧**：根据各源独立阈值显示陈旧；陈旧国内、海外或飞书状态不得混成“截至现在”的总量。阈值待业务确认，Demo 固定时钟不代表生产 SLA。
- **无历史成功值**：显示“未接入/暂无有效快照”，不是0。部分账号/仓库缺失时展示缺口范围，不把其它仓的成功扩展为全市场成功。

## 成本覆盖与可加总边界

库存估算货值只使用已确认映射、有效实物数量和相应版本的不含运费单位成本；飞书在途货值使用有效未收货数量。可售、锁定和来源在途是独立指标。现役 available 型 `inventory.quantity` 不能作为实物估值数量直接复用。

沿用 [产品货值规则](product-plan-v4.md#货值口径已确认不含运费其余正式口径待确认)，本期不做运费分摊、不把物流费用叠加进阶段/市场/历史估值。含运费或口径未知的成本在澄清前列为未估值缺口。

展示已估值小计、成本覆盖数量/范围、缺成本数量、未映射数量、陈旧/待对账范围。缺成本不按0，异币无明确汇率/日期/版本不合计；不同单位须先有明确换算关系。

即使成本覆盖100%，来源未对齐或收货证据不足仍不能给出去重总货值。国内、在途、海外分项允许独立观察，只有完整且无重复的授权范围才开放整体合计；不以“看起来恒定”为验收目标。

## 操作日志和证据链

目标链路：`request_id → source_batch/record/version → mapping_version → shipment/item/receipt_evidence → snapshot_batch → operation_log`。同一次跨步骤操作共享 correlation ID；事实先后由业务时间、采集时间和提交时间分别说明。

日志至少包含主体（用户/系统与来源）、时间、动作、对象 ID、前后版本/变化、市场/仓库、公司货号/69编码/外部 SKU、货票和批次、结果及失败原因；没有解析出商品时保留外部键，不编造货号。

成功业务变化与日志同事务；失败/拒绝另记失败记录，不能冒充成功。来源原始响应按受控证据权限保存；日志不记录密钥、cookie/token、敏感联系人信息，不通过前后值向无金额权限用户泄漏成本。

## 后续真实接入验收场景

1. 正序240+100 → 240+0待确认 → 来源340+0；到货/API过程无 inventory 加法，国内减少仅来自聚水潭。
2. 逆序库存340、飞书在途100：无证据时不出440或猜成340；有明确证据后去重但不改原始来源事实。
3. 发100/到60/剩40、多 SKU 到货不齐、票级状态冲突、超收拒绝；重复累计60不累加，部分证据不整票吸收。
4. 缺映射/停用/换绑保留原量与历史映射；缺账号/多运单候选/跨市场绑定均拒绝自动关联。
5. 重放不重复写；乱序不回滚最新；同版本异内容报冲突；撤销已核对收货进入重核而不反向改库存。
6. 抓取失败/缺页/缺仓/字段错误不发布，旧值和成功时间不变；首次失败显示未知，陈旧范围不静默归零或全局成功。
7. 缺成本/异币/单位冲突和待对账使覆盖/合计正确降级；无金额权限的 DTO、导出和日志均不泄露金额。
8. 从页面每条指标可追溯到来源批次、映射版本、业务/收货证据和操作日志；Demo 纯函数通过不代表真实 RLS、并发、账号或来源已验收。
